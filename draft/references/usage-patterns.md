# draft:answer-gui 使い方パターン集

実戦で使ったうえで「これがロバスト」と確認できたパターンを集約。スキル本体（answer-gui.md）は仕様書、こちらは「どう使うか」の実装ガイド。

## モード選択フロー

```
質問数は？
├─ 1〜2問・即決系          → mode 省略 or "yes-no"
├─ 3問以上・各 context が長い → mode: "wizard"（1問ずつ画面）
├─ 多数のタスク仕分け（10件超） → mode: "table" ★ 主力
└─ Notion 等の差分確認        → mode: "diff-table"
```

---

## ★ パターン A: タスク仕分け（table モード）

**用途**: daily-report 振り分け / Asana triage / 着手予定一括設定 / 期日見直し  

### 必須ルール

1. **`title` には必ず `[PJ名]` を含める**  
   PJ名がないと「どのタスクがどの PJ か」視覚識別できない。PJ なしは `[(なし)]`。
2. **items は PJ ごとにまとめてソート**  
   同じ PJ のタスクが連続するように並べる（group by ではなく単なる sort で十分）。
3. **`group` フィールドで PJ 列を独立表示（推奨）**  
   `items[].group` に PJ 名を入れると、独立カラムとして表示され、同 PJ 連続行は2行目以降が空欄になる（daily-report の表と同じ視覚効果）。
4. **`context` には期限・経過日数・補足情報を入れる**  
   タスク名だけでは判断材料が足りないため。
5. **memo を活用させる**  
   options で表現しきれない補足（完了済み・依頼先・関連 Slack 引用・別日提案）はすべて memo で受け取る。出力後に memo を必ず読む。

### JSON 例（着手予定一括設定）

```json
{
  "mode": "table",
  "items": [
    {
      "id": "<page_id>",
      "group": "勉強会",
      "title": "会場の候補を調べる",
      "context": "提案: 今週着手",
      "options": ["OK 提案通り", "別日（memo）", "スキップ"]
    },
    {
      "id": "<page_id>",
      "group": "勉強会",
      "title": "案内文の下書きを作る",
      "context": "提案: 今週着手",
      "options": ["OK 提案通り", "別日（memo）", "スキップ"]
    },
    {
      "id": "<page_id>",
      "group": "読書会",
      "title": "次回の本を選ぶ",
      "context": "提案: 来週着手",
      "options": ["OK 提案通り", "別日（memo）", "スキップ"]
    }
  ]
}
```

### 出力後の処理

- `choice == "OK 提案通り"` → 提案値で反映
- `choice == "別日（memo）"` → memo から日付パースして反映
- `choice == "スキップ"` → 何もしない
- choice が空でも memo に記入があれば**それを優先**（提案がイケてなかった脱出口）
- memo に「完了してる」「存在しない」と書かれていたら **complete / archive にアクションを切り替える**

## パターン B: 仕分け（やる/伸ばす/捨てる）

**用途**: daily-report の3レーン振り分け（期限超過・今日締切・着手時期到来）  

### options 設計

```
["やる", "伸ばす", "捨てる"]
```

シンプルな3択。memo に理由・新期日・依頼先を書く。

「捨てる」の意味は文脈で2つに分岐:
- **削除（archive）**: 「タスクが存在しない」「完全に不要」
- **完了化（complete）**: 「実はもう完了している」「他の手段で解決済み」

→ memo の文言から Claude 側で判別する（「完了してる」「対応済み」は完了、「存在しない」「不要」は archive）。

## パターン C: 差分確認（diff-table）

**用途**: Notion フィールド更新の最終確認  
**例**: タスクの期日と進捗を見比べる

### 制約

- **メモ欄なし**。理由付け・依存関係メモが必要なら **table モードに切り替える**
- 1行 = 1フィールド変更（current vs proposed）
- チェックで approved = true / false を切り替え

### 複数タスクの一括反映

`id` を `<page_id>:<field>` 形式にして、出力で parse すれば1つの GUI で複数タスクの複数フィールドを処理できる:

```json
{ "id": "<page_id>:status", "label": "[完了] タスク名", "current": "進行中", "proposed": "完了" },
{ "id": "<page_id>:due",    "label": "[期日] タスク名", "current": "2026-04-29", "proposed": "2026-05-02" }
```

## パターン D: 方針合意（wizard）

**用途**: 複数論点の方針合意（個別仕分けではなく抽象的な判断）

table モードと使い分け:
- table: 個別タスクの仕分け
- wizard: 「アプローチA か B か」「ルールをどう変えるか」など方針レベル

---

## やってはいけない

- ❌ **PJ名を title に含めない**: タスク名だけだとどの文脈か分からない
- ❌ **items を PJ でソートしない**: 同 PJ のタスクが点在すると視認性が落ちる
- ❌ **diff-table でメモが必要な場面で使う**: メモ欄がない仕様。table モードに切り替える
- ❌ **wizard で多数のタスクを1問ずつ聞く**: 全体俯瞰できず比較判断しづらい
- ❌ **context に期限を書かずタスク名だけ**: 判断材料が足りない

## トラブルシュート

| 症状 | 原因 | 対処 |
|---|---|---|
| 字が小さい | THEME["font"] のデフォルト | `THEME["font"]` を編集（design-tokens.md 参照） |
| 一部の文字サイズが変わらない | 個別のサイズ指定 | テーマ側の指定に合わせる |
| 同じ PJ が point 隔離されて表示 | items を sort してない | Claude 側で PJ ごとに sort してから渡す |
| メモ欄が出ない | mode が diff-table | mode を "table" に切り替え |
| 同 PJ 連続行が PJ 名で埋め尽くされる | `group` フィールド未使用 | 各 item に `group: "<PJ名>"` を追加 |
