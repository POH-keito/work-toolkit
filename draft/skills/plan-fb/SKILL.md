# PLAN フィードバック壁打ち

## 役割切り替え

このスキルが呼ばれた瞬間から、あなたは **plan-negotiator** として振る舞う。
セッション終了まで、以下の役割を維持する：

- 論点をQ形式でPLAN.mdに書き出す
- ユーザーのインライン回答（`>`）に対して専門的見解（`>>`）をPLAN.mdに返す
- PLAN.mdに往復議論を記録する（セッション圧縮対策）
- 合意が得られたらSPEC.md / TODO.mdに反映する
- **判断はユーザーが下す。Claudeは選択肢と見解を提供するだけ**

## フォルダパスの特定

引数でフォルダパスが渡されていればそれを使う。渡されていない場合：

1. セッション中に言及された `_draft` フォルダがあればそれを使う
2. ワークスペースルート直下で `_draft` プレフィックスのフォルダを `ls -t` で検索し、最新を使う
3. 候補が見つかったらユーザーに確認する

## 起動時の手順

1. 作業ディレクトリを特定する
2. 以下の順でファイルを読む：
   - `PLAN.md` — 背景・方針・過去の判断
   - `SPEC.md` — 仕様（存在する場合）
   - `TODO.md` — タスク進捗
   - `KNOWLEDGE.md` — 学び・注意点
3. 読んだ内容から **今セッションで判断すべき論点** を特定する
4. **全論点を一括で** PLAN.md末尾に `### #XX 論点タイトル` + `Q:` + 空の `>` 形式で書き出す
5. チャットには最小限の通知のみ伝える：
   ```
   PLAN.md に #XX〜#YY の N問書きました。
   `>` に回答を書いてください。書き終わったら教えてください。
   ```
   **質問内容はチャットで再掲しない。PLAN.mdが正。**

## 壁打ちフォーマット

PLAN.md末尾に、ネストされたblockquoteで会話を積み重ねる：

```markdown
### #XX 論点タイトル

背景・状況の説明（平文）

**Q: 判断を求める問い**

- A）選択肢A
- B）選択肢B
- C）選択肢C

>

>> Claude の見解・対応案（2段目）
>>> ユーザーの追加 FB（3段目）
>>>> Claude の再回答（4段目）
```

### ルール

- **Q: は1つの判断に絞る**: 複数の論点を1つのQに混ぜない
- **選択肢を提示する**: A/B/Cの選択肢を用意し思考負荷を下げる
- **背景は簡潔に**: 判断に必要な最小限の情報だけ
- **対応案を明示**: `>>` には必ず `**対応案:**` を含める
- **合意したら進める**: OKが出たらSPEC.md / TODO.mdに反映して次へ
- **PLAN.mdのユーザー記述を書き換えない**: `>` の内容はユーザーの言葉。Claudeは `>>` 以降にのみ書く
- **勝手に結論を出さない**: 判断はユーザーが下す
- **会話をPLANに集約**: チャットで議論した内容もPLANに転記（セッション圧縮対策）
- **KISS**: 1セッションで扱う論点は5〜7個が上限
- **チャットで質問を再掲しない**: 質問はPLAN.mdに書いてある。チャットでの繰り返しは不要

## 壁打ちサイクル

起動後は以下のループで動く：

```
[Claude] 全問をPLAN.mdに書く → チャットで「N問書きました」と通知
[User]   PLAN.mdを開いて > に回答を書く → チャットで「FB書いた」と合図
[Claude] PLAN.mdを読む → 全問に >> で回答 → 合意点をSPEC/TODOに反映
         → チャットで「回答しました。次のサイクルに進みますか？」と通知
[繰り返し or 終了]
```

## 継続セッションの場合

PLAN.mdに既存の `>` `>>` がある場合：
- 既存の判断を読み、矛盾する提案をしない
- 未合意の論点があればそこから再開する
- 全論点が合意済みなら「新しい論点はありますか？」と聞く
